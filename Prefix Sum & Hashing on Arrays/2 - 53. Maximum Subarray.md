# 53. Maximum Subarray

<details>
<summary>📝 Problem Statement</summary>

Given an integer array `nums`, find the **non-empty subarray with the largest sum** and return its sum.

### Example 1

```text
Input:  nums = [-2,1,-3,4,-1,2,1,-5,4]
Output: 6
Explanation: The subarray [4,-1,2,1] has the largest sum 6.
```

### Example 2

```text
Input:  nums = [1]
Output: 1
Explanation: The subarray [1] has the largest sum 1.
```

### Example 3

```text
Input:  nums = [5,4,-1,7,8]
Output: 23
Explanation: The subarray [5,4,-1,7,8] has the largest sum 23.
```

### Constraints

* `1 <= nums.length <= 10⁵`
* `-10⁴ <= nums[i] <= 10⁴`

</details>

<details>
<summary>🐢 Brute Force — Check Every Subarray</summary>

### Approach

The simplest approach is to consider **every possible subarray**.

For every pair of starting and ending indices, calculate the sum of that subarray and keep track of the maximum sum found.

```java
class Solution {

    public int maxSubArray(int[] nums) {

        int n = nums.length;
        int maxSum = Integer.MIN_VALUE;

        for (int i = 0; i < n; i++) {

            for (int j = i; j < n; j++) {

                int sum = 0;

                for (int k = i; k <= j; k++) {
                    sum += nums[k];
                }

                maxSum = Math.max(maxSum, sum);
            }
        }

        return maxSum;
    }
}
```

### Complexity

* **Time:** `O(n³)`
* **Space:** `O(1)`

We use three loops: two to generate every subarray and one to calculate its sum.

</details>

<details>
<summary>⚡ Better Approach — Running Sum</summary>

### Approach

In the brute-force solution, we repeatedly calculate the same elements.

Instead, once we choose a starting index `i`, we can keep extending the subarray and maintain its running sum.

For example, while extending:

```text
[4]
[4, -1]
[4, -1, 2]
[4, -1, 2, 1]
```

we don't need to recalculate each sum from scratch.

We simply do:

```text
sum += nums[j]
```

and update the maximum whenever the current sum is larger.

### Code

```java
class Solution {

    public int maxSubArray(int[] nums) {

        int n = nums.length;
        int maxSum = Integer.MIN_VALUE;

        for (int i = 0; i < n; i++) {

            int sum = 0;

            for (int j = i; j < n; j++) {

                sum += nums[j];
                maxSum = Math.max(maxSum, sum);
            }
        }

        return maxSum;
    }
}
```

### Complexity

* **Time:** `O(n²)`
* **Space:** `O(1)`

</details>

<details>
<summary>🚀 Optimal Approach — Kadane's Algorithm</summary>

### Intuition

Let's look at what happens when we build a subarray from left to right.

Suppose we currently have a subarray whose running sum is `sum`.

Now we encounter the next number.

There are two possibilities:

1. **Our current sum is positive**
   Keeping this sum can help the next elements because we are carrying some positive contribution forward.

2. **Our current sum becomes negative**
   A negative sum can only make any future subarray worse.

For example:

```text
[-5, 4, 6]
```

If we keep `-5` and continue:

```text
-5 + 4 + 6 = 5
```

But if we discard the negative prefix:

```text
4 + 6 = 10
```

So once our running sum becomes negative, there is no reason to carry it forward.

We can simply **start a new subarray from the next element**.

Therefore:

> If the running sum becomes negative, reset it to `0`.

### But what about negative numbers?

Consider:

```text
[-5, -2, -8]
```

If we reset the sum to `0` after every negative number and only update the answer afterward, we might incorrectly return `0`.

But the problem requires a **non-empty subarray**, so `0` cannot be the answer.

Instead, we update `maxSum` **before resetting the running sum**.

For the above array:

```text
-5 → maxSum = -5
-2 → maxSum = -2
-8 → maxSum = -2
```

Therefore, the largest negative number, `-2`, is correctly returned.

### Step-by-Step Example

Consider:

```text
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

We keep a running `sum` and the best answer `maxSum`.

```text
num     sum        maxSum
--------------------------
-2      -2          -2
 1       1           1
-3      -2           1
 4       4           4
-1       3           4
 2       5           5
 1       6           6
-5       1           6
 4       5           6
```

The maximum value reached by `sum` is `6`.

The corresponding subarray is:

```text
[4, -1, 2, 1]
```

### Why resetting works

Suppose our current running sum is negative:

```text
sum < 0
```

Any future subarray that includes this negative sum would be better off **without it**.

So we discard it:

```text
sum = 0
```

This means the next element can become the beginning of a new subarray.

### Algorithm

1. Start with `sum = 0`.
2. Set `maxSum` to `Integer.MIN_VALUE` so that arrays containing only negative numbers are handled correctly.
3. Traverse every number.
4. Add the number to `sum`.
5. Update `maxSum`.
6. If `sum` becomes negative, reset it to `0`.
7. Return `maxSum`.

### Complexity

|              | Complexity |
| ------------ | ---------- |
| ⏱️ **Time**  | `O(n)`     |
| 💾 **Space** | `O(1)`     |

</details>

<details>
<summary>💻 Optimal Code</summary>

```java
class Solution {

    public int maxSubArray(int[] nums) {

        int sum = 0;
        int maxSum = Integer.MIN_VALUE;

        for (int num : nums) {

            sum += num;

            // Update before resetting for all-negative arrays
            maxSum = Math.max(maxSum, sum);

            // A negative prefix only hurts future subarrays
            if (sum < 0) {
                sum = 0;
            }
        }

        return maxSum;
    }
}
```

</details>

<details>
<summary>⚠️ Important Detail — Why update <code>maxSum</code> before resetting?</summary>

Consider:

```text
nums = [-3, -2, -5]
```

If we reset first:

```java
if (sum < 0) {
    sum = 0;
}

maxSum = Math.max(maxSum, sum);
```

we would keep comparing against `0`, which could incorrectly produce `0`.

But `0` does **not** represent a valid subarray because the subarray must be non-empty.

Instead, we do:

```java
maxSum = Math.max(maxSum, sum);

if (sum < 0) {
    sum = 0;
}
```

This ensures that every individual negative number gets a chance to update the answer.

For:

```text
[-3, -2, -5]
```

the answer becomes:

```text
-2
```

which is the largest possible subarray sum.

</details>

<details>
<summary>🧠 Pattern to Remember</summary>

**Kadane's Algorithm** can be remembered with one simple idea:

> **A negative running sum can only hurt a future subarray, so discard it.**

```text
Add current element
        ↓
Update maximum
        ↓
Is running sum negative?
        ↓
  Yes → Reset to 0
  No  → Keep it
```

The key condition is:

```java
if (sum < 0) {
    sum = 0;
}
```

And remember:

> **Update the answer before resetting the sum**, otherwise an all-negative array can give the wrong answer.

</details>
