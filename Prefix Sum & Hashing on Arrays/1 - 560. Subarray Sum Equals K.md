# 560. Subarray Sum Equals K

<details>
<summary>📝 Problem Statement</summary>

Given an integer array `nums` and an integer `k`, return the **total number of non-empty contiguous subarrays** whose sum is exactly `k`.

### Example 1

```text
Input:  nums = [1,1,1], k = 2
Output: 2
```

### Example 2

```text
Input:  nums = [1,2,3], k = 3
Output: 2
```

### Constraints

* `1 <= nums.length <= 2 * 10⁴`
* `-1000 <= nums[i] <= 1000`
* `-10⁷ <= k <= 10⁷`

</details>

<details>
<summary>🐢 Brute Force — Check Every Subarray</summary>

### Approach

The simplest approach is to generate **every possible subarray**.

For every starting index `i` and ending index `j`, calculate the complete sum of that subarray and check whether it equals `k`.

### Code

```java
class Solution {

    public int subarraySum(int[] nums, int k) {

        int n = nums.length;
        int cnt = 0;

        for (int i = 0; i < n; i++) {

            for (int j = i; j < n; j++) {

                int sum = 0;

                for (int x = i; x <= j; x++) {
                    sum += nums[x];
                }

                if (sum == k) {
                    cnt++;
                }
            }
        }

        return cnt;
    }
}
```

### Complexity

* **Time:** `O(n³)`
* **Space:** `O(1)`

There are three loops:

1. Choose the starting index.
2. Choose the ending index.
3. Calculate the sum of the selected subarray.

</details>

<details>
<summary>⚡ Better Approach — Running Sum</summary>

### Approach

The brute-force approach repeatedly calculates the same elements.

For example, after calculating the sum of:

```text
[1, 2, 3]
```

if we extend the subarray to:

```text
[1, 2, 3, 4]
```

we don't need to calculate `1 + 2 + 3` again.

We can simply keep the previous sum and add the new element:

```text
sum += nums[j]
```

So, for every starting index, extend the subarray and maintain its running sum.

### Code

```java
class Solution {

    public int subarraySum(int[] nums, int k) {

        int n = nums.length;
        int cnt = 0;

        for (int i = 0; i < n; i++) {

            int sum = 0;

            for (int j = i; j < n; j++) {

                sum += nums[j];

                if (sum == k) {
                    cnt++;
                }
            }
        }

        return cnt;
    }
}
```

### Complexity

* **Time:** `O(n²)`
* **Space:** `O(1)`

</details>

<details>
<summary>🚀 Optimal Approach — Prefix Sum + HashMap</summary>

### Intuition

Instead of checking every possible starting point separately, we can use **prefix sums** to find valid subarrays while traversing the array only once.

Suppose we are currently at index `i`, and the sum of all elements from the beginning up to `i` is:

```text
sum = x
```

Now, we want to find a subarray ending at `i` whose sum is `k`.

Imagine that at some earlier index `j`, the prefix sum was `y`.

The sum of elements between `j + 1` and `i` would be:

```text
x - y
```

We want this subarray sum to be `k`.

Therefore:

```text
x - y = k
```

So the earlier prefix sum we are looking for must be:

```text
y = x - k
```

This gives us the key observation:

> At every index, if we have already seen a prefix sum equal to `currentSum - k`, then the elements after that prefix up to the current index form a valid subarray.

### Why use a HashMap?

Now we need to quickly answer:

> "Have we seen `currentSum - k` before?"

We store every prefix sum in a HashMap:

```text
prefix sum → frequency
```

We store the **frequency**, not just whether it exists, because the same prefix sum can occur multiple times.

If `currentSum - k` has appeared 3 times, then there are **3 different subarrays** ending at the current index whose sum is `k`.

### Step-by-Step Example

Consider:

```text
nums = [1, 1, 1]
k = 2
```

Initially:

```text
sum = 0
cnt = 0
map = {0 : 1}
```

We start with `0 : 1` because a prefix sum of `0` exists before the array starts.

#### First `1`

```text
sum = 1
needed = 1 - 2 = -1
```

`-1` has not appeared.

Store `1`:

```text
map = {0:1, 1:1}
```

#### Second `1`

```text
sum = 2
needed = 2 - 2 = 0
```

`0` has appeared once.

So we found one valid subarray:

```text
[1, 1]
```

Now:

```text
cnt = 1
```

Store `2`:

```text
map = {0:1, 1:1, 2:1}
```

#### Third `1`

```text
sum = 3
needed = 3 - 2 = 1
```

`1` has appeared once.

So we found another valid subarray:

```text
[1, 1]
```

Now:

```text
cnt = 2
```

Therefore, the answer is `2`.

### Algorithm

1. Create a HashMap storing `prefixSum → frequency`.
2. Put `0 → 1` initially.
3. Traverse the array.
4. Add the current element to `sum`.
5. Find `sum - k` in the map.
6. Add its frequency to `cnt`.
7. Store the current `sum` in the map.
8. Return `cnt`.

### Complexity

|              | Complexity |
| ------------ | ---------- |
| ⏱️ **Time**  | `O(n)`     |
| 💾 **Space** | `O(n)`     |

</details>

<details>
<summary>💻 Optimal Code</summary>

```java
class Solution {

    public int subarraySum(int[] nums, int k) {

        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, 1); // Prefix sum before the array starts

        int sum = 0;
        int cnt = 0;

        for (int num : nums) {

            sum += num;

            // Previous prefix needed to form sum k
            int rem = sum - k;

            cnt += map.getOrDefault(rem, 0);

            // Store frequency of current prefix sum
            map.put(sum, map.getOrDefault(sum, 0) + 1);
        }

        return cnt;
    }
}
```

</details>

<details>
<summary>💡 Why do we use <code>map.put(0, 1)</code>?</summary>

Consider:

```text
nums = [1, 2]
k = 3
```

When we reach `2`:

```text
sum = 3
```

We need a previous prefix sum of:

```text
3 - 3 = 0
```

There is no actual element before the array, but we can think of the prefix sum before index `0` as `0`.

This allows us to count the complete subarray:

```text
[1, 2]
```

Therefore, we initialize:

```java
map.put(0, 1);
```

The `1` means that prefix sum `0` has occurred once.

</details>

<details>
<summary>⚠️ Why can't we use Sliding Window?</summary>

Sliding Window does not work reliably here because the array can contain **negative numbers**.

For example:

```text
[2, -2, 3]
```

Adding an element does not always increase the sum, and removing an element does not always decrease it.

Therefore, we cannot reliably decide:

> "The sum is too large, so move `left`."

The Prefix Sum + HashMap approach works with **positive, zero, and negative values**.

</details>

<details>
<summary>🧠 Pattern to Remember</summary>

For problems asking to **count subarrays with a given sum**, think:

> **Prefix Sum + HashMap**

Build the idea logically:

```text
Current prefix sum = x
        ↓
Need an earlier prefix
        ↓
Current prefix - Earlier prefix = k
        ↓
Earlier prefix = x - k
        ↓
Store previous prefix sums
        ↓
Look for x - k
        ↓
Add its frequency to the answer
```

The key line is:

```java
cnt += map.getOrDefault(sum - k, 0);
```

</details>
