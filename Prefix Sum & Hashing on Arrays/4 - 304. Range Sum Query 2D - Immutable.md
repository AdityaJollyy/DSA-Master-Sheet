# 304. Range Sum Query 2D - Immutable

<details>
<summary>📝 Problem Statement</summary>

Given a 2D matrix `matrix`, handle multiple queries of the following type:

* Calculate the **sum of all elements inside the rectangle** defined by its upper-left corner `(row1, col1)` and lower-right corner `(row2, col2)`.

Implement the `NumMatrix` class:

* `NumMatrix(int[][] matrix)` — initializes the object with the matrix.
* `int sumRegion(int row1, int col1, int row2, int col2)` — returns the sum of the elements inside the given rectangle.

The `sumRegion` operation must work in **`O(1)` time**.

### Example 1

![Example 1](/images/4c.png)

```text
Input
["NumMatrix", "sumRegion", "sumRegion", "sumRegion"]
[[[[3, 0, 1, 4, 2],
   [5, 6, 3, 2, 1],
   [1, 2, 0, 1, 5],
   [4, 1, 0, 1, 7],
   [1, 0, 3, 0, 5]]],
 [2, 1, 4, 3],
 [1, 1, 2, 2],
 [1, 2, 2, 4]]

Output
[null, 8, 11, 12]
```

The three queries correspond to the **red, green, and blue** rectangles in the image.

### Constraints

* `m == matrix.length`
* `n == matrix[i].length`
* `1 <= m, n <= 200`
* `-10⁴ <= matrix[i][j] <= 10⁴`
* `0 <= row1 <= row2 < m`
* `0 <= col1 <= col2 < n`
* At most `10⁴` calls will be made to `sumRegion`.

</details>

<details>
<summary>🐢 Brute Force — Traverse the Rectangle</summary>

### Approach

For every query, directly visit every element inside the requested rectangle and add them.

For a query from `(row1, col1)` to `(row2, col2)`, we iterate through all rows from `row1` to `row2` and all columns from `col1` to `col2`.

### Code

```java
class NumMatrix {

    int[][] matrix;

    public NumMatrix(int[][] matrix) {
        this.matrix = matrix;
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {

        int sum = 0;

        for (int i = row1; i <= row2; i++) {
            for (int j = col1; j <= col2; j++) {
                sum += matrix[i][j];
            }
        }

        return sum;
    }
}
```

### Complexity

* **Time:** `O(m × n)` per query in the worst case
* **Space:** `O(1)`

This becomes inefficient when there are many queries because the same cells may be visited repeatedly.

</details>

<details>
<summary>🚀 Optimal Approach — 2D Prefix Sum</summary>

### Intuition

We can **precompute information once** and use it to answer every query quickly.

The idea is similar to a normal 1D prefix sum.

In 1D, we store the sum from the beginning of the array up to every index.

For a 2D matrix, we do the same thing:

> For every position, store the sum of the entire rectangle from the top-left corner `(0, 0)` to that position.

### Calculating the 2D Prefix Sum

To calculate the prefix sum at a position, we can combine:

* The region **above**
* The region **to the left**
* The **current element**

But the top-left region is present in both the above and left regions, so it gets counted twice.

Therefore, we subtract that overlapping region once.

![How to Calculate 2D Prefix Sum](/images/4a.png)

So:

```text
sum[i][j]
=
matrix[i-1][j-1]
+ sum[i-1][j]
+ sum[i][j-1]
- sum[i-1][j-1]
```

### Why do we use an extra row and column?

Instead of making `sum` the same size as `matrix`, we create:

```text
(m + 1) × (n + 1)
```

The first row and first column are left as `0`.

This means we don't need special cases for the first row or first column.

It also makes the formula consistent for every position.

Because of this:

```text
matrix[i][j] → sum[i + 1][j + 1]
```

---

### Calculating a Range Sum

Now suppose we want the sum of a rectangle from:

```text
(row1, col1)
```

to:

```text
(row2, col2)
```

We start with the prefix sum containing the **entire region from `(0,0)` to `(row2,col2)`**.

Then we remove the unwanted parts.

![Calculate Range Sum in O(1)](/images/4b.png)

### 1. Start with the complete region

```text
A = sum[row2 + 1][col2 + 1]
```

This contains everything we need **plus** some unwanted elements.

### 2. Remove the region above

```text
B = sum[row1][col2 + 1]
```

So:

```text
A - B
```

### 3. Remove the region to the left

```text
C = sum[row2 + 1][col1]
```

So:

```text
A - B - C
```

### 4. Add the overlap back

There is one problem.

The top-left overlapping region was removed **twice**:

* once when subtracting `B`
* once when subtracting `C`

So we add it back once:

```text
D = sum[row1][col1]
```

Therefore:

```text
rangeSum = A - B - C + D
```

So the final formula is:

```text
rangeSum =
    sum[row2 + 1][col2 + 1]
    - sum[row1][col2 + 1]
    - sum[row2 + 1][col1]
    + sum[row1][col1]
```

This is the **inclusion-exclusion** idea.

### Why is `sumRegion()` O(1)?

After building the prefix-sum matrix, every query only needs:

* 4 array accesses
* 2 subtractions
* 1 addition

The size of the requested rectangle does not matter.

Therefore, every `sumRegion()` call takes **`O(1)` time**.

### Complexity

| Operation        |       Time |      Space |
| ---------------- | ---------: | ---------: |
| Build prefix sum | `O(m × n)` | `O(m × n)` |
| `sumRegion()`    |     `O(1)` |     `O(1)` |

</details>

<details>
<summary>💻 Optimal Code</summary>

```java
class NumMatrix {

    int[][] sum;

    public NumMatrix(int[][] matrix) {

        int m = matrix.length;
        int n = matrix[0].length;

        // Extra row and column avoid boundary checks
        sum = new int[m + 1][n + 1];

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {

                sum[i][j] = matrix[i - 1][j - 1]
                          + sum[i - 1][j]
                          + sum[i][j - 1]
                          - sum[i - 1][j - 1];
            }
        }
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {

        // Prefix-sum array uses 1-based indexing
        return sum[row2 + 1][col2 + 1]
             - sum[row1][col2 + 1]
             - sum[row2 + 1][col1]
             + sum[row1][col1];
    }
}
```

</details>

<details>
<summary>💡 Why do we use <code>row2 + 1</code> and <code>col2 + 1</code>?</summary>

The original matrix uses **0-based indexing**.

But our prefix-sum matrix has an extra row and column at the beginning.

Therefore:

```text
matrix[i][j] → sum[i + 1][j + 1]
```

So an original matrix position `(row2, col2)` corresponds to:

```text
(row2 + 1, col2 + 1)
```

This is why the first term is:

```java
sum[row2 + 1][col2 + 1]
```

The same offset explains the other terms in the range-sum formula.

</details>

<details>
<summary>⚠️ Important Formula</summary>

### Building the Prefix Sum

Think:

```text
TOP + LEFT - OVERLAP + CURRENT
```

```text
sum[i][j]
=
matrix[i-1][j-1]
+ sum[i-1][j]
+ sum[i][j-1]
- sum[i-1][j-1]
```

### Querying a Range

Think:

```text
BIG REGION - TOP - LEFT + OVERLAP
```

```text
rangeSum
=
sum[row2+1][col2+1]
- sum[row1][col2+1]
- sum[row2+1][col1]
+ sum[row1][col1]
```

</details>

<details>
<summary>🧠 Pattern to Remember</summary>

For **2D range-sum queries**:

```text
Build 2D Prefix Sum
        ↓
Store top-left rectangle sums
        ↓
Use inclusion-exclusion
        ↓
Answer each query in O(1)
```

The main idea is:

> **Take the complete region, remove the unwanted top and left parts, and add their overlap back once.**
