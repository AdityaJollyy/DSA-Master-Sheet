# 523. Continuous Subarray Sum

<details>
<summary>📝 Problem Statement</summary>

Given an integer array `nums` and an integer `k`, return `true` if `nums` contains a **good subarray**, otherwise return `false`.

A **good subarray** satisfies:

* Its length is **at least 2**.
* The sum of its elements is a **multiple of `k`**.

In other words, for a subarray with sum `sum`:

```text
sum % k == 0
```

### Example 1

```text
Input:
nums = [23, 2, 4, 6, 7]
k = 6

Output:
true
```

Explanation:

```text
[2, 4]
```

has sum:

```text
2 + 4 = 6
```

and:

```text
6 % 6 = 0
```

So it is a good subarray.

### Example 2

```text
Input:
nums = [23, 2, 6, 4, 7]
k = 6

Output:
true
```

The entire array has sum:

```text
23 + 2 + 6 + 4 + 7 = 42
```

and:

```text
42 % 6 = 0
```

So it is a good subarray.

### Example 3

```text
Input:
nums = [23, 2, 6, 4, 7]
k = 13

Output:
false
```

</details>

---

<details>
<summary>🐢 Brute Force — 3 Loops</summary>

### 💡 Intuition

The most straightforward approach is to generate **every possible subarray** and calculate its sum.

We need three loops:

```text
Loop 1 → choose starting index i
Loop 2 → choose ending index j
Loop 3 → calculate sum from i to j
```

For every subarray, we check two conditions:

```text
length >= 2
```

and

```text
sum % k == 0
```

If both are true, we can immediately return `true`.

### Code

```java
class Solution {

    public boolean checkSubarraySum(int[] nums, int k) {

        for (int i = 0; i < nums.length; i++) {

            for (int j = i + 1; j < nums.length; j++) {

                int sum = 0;

                for (int x = i; x <= j; x++) {
                    sum += nums[x];
                }

                if (sum % k == 0) {
                    return true;
                }
            }
        }

        return false;
    }
}
```

### Complexity

* **Time:** `O(N³)`
* **Space:** `O(1)`

</details>

---

<details>
<summary>⚡ Better Approach — 2 Loops</summary>

### 💡 Intuition

In the brute-force solution, we repeatedly calculate the same elements.

For example, once we choose a starting index `i`, instead of calculating the sum of every subarray from scratch, we can **keep extending the subarray and maintain its running sum**.

Suppose:

```text
nums = [4, -1, 2, 1]
```

and we choose:

```text
i = 0
```

As we move `j` forward, the subarray keeps growing:

```text
[4]
[4, -1]
[4, -1, 2]
[4, -1, 2, 1]
```

We don't need to recalculate each sum from scratch.

We simply keep adding the newly included element:

```java
sum += nums[j];
```

So the sums are built like:

```text
[4]              → sum = 4
[4, -1]          → sum = 4 + (-1)
[4, -1, 2]       → sum = previousSum + 2
[4, -1, 2, 1]    → sum = previousSum + 1
```

Therefore, once we choose the starting index `i`, we can extend the subarray with `j` and maintain the running sum in `O(1)` time.

After adding each element, simply check:

```text
sum % k == 0
```

and make sure the subarray contains at least two elements.

### Code

```java
class Solution {

    public boolean checkSubarraySum(int[] nums, int k) {

        for (int i = 0; i < nums.length; i++) {

            int sum = 0;

            for (int j = i; j < nums.length; j++) {

                sum += nums[j];

                // Length must be at least 2
                if (j > i && sum % k == 0) {
                    return true;
                }
            }
        }

        return false;
    }
}
```

### Why Is This Better?

The brute-force solution uses a third loop to calculate:

```text
nums[i] + nums[i+1] + ... + nums[j]
```

again and again.

Here, when `j` moves one step forward, we only add the **new element**:

```java
sum += nums[j];
```

So the third loop is removed.

### Complexity

* **Time:** `O(N²)`
* **Space:** `O(1)`

</details>

<details>
<summary>🚀 Optimal Approach — Prefix Sum + Remainder + HashMap</summary>

### 🧠 Let's Build the Intuition From the Beginning

The better solution is `O(N²)` because we still try every possible starting point.

To reach `O(N)`, we need to avoid explicitly checking every possible subarray.

The important thing to notice is that we **do not actually care about the exact sum**.

We only care whether the sum is a **multiple of `k`**.

That means we care about:

```text
sum % k
```

This is where the key observation comes from.

---

### Step 1: Think About Prefix Sums

Suppose we have:

```text
nums = [23, 2, 4, 6, 7]
k = 6
```

Consider the prefix sums:

```text
23
25
29
35
42
```

For a subarray from `i + 1` to `j`, its sum is:

```text
prefixSum[j] - prefixSum[i]
```

We need this subarray sum to be a multiple of `k`.

Therefore:

```text
(prefixSum[j] - prefixSum[i]) % k == 0
```

Now let's simplify this.

---

Mathematically:

```text
(prefixSum[j] - prefixSum[i]) % k == 0

                ↓
prefixSum[j] % k == prefixSum[i] % k

                ↓

subarray sum is a multiple of k
```
> **If two prefix sums have the same remainder when divided by `k`, the subarray between them has a sum that is a multiple of `k`.**

---

### Step 2: This Becomes a "Longest Subarray with Sum K" Type Pattern

In any prefix sum problem, the HashMap stores what we have already seen: our **previous** states. Let's compare the standard problem with our current one to see exactly how we isolate that previous state to figure out what to search for.

**1. The Standard Problem (Sum exactly K)**
For the usual longest subarray problem, we look for a subarray where the sum is exactly `K`:

```text
currentSum - prefixSum = K
```

To find out if this valid subarray exists, we use basic algebra to isolate `previousSum` (the past state) on one side:

```text
currentSum - K = prefixSum
```

Because the right side (`previousSum`) is what is physically stored in our HashMap, the left side (`currentSum - K`) is what we must **search for** as our target.

**2. The Divisible by K Problem**
Here, we don't need the exact difference to be `K`. We just need it to be a multiple of `k`. The core equation is:

```text
(currentSum - prefixSum) % k = 0
```

Mathematically, this simplifies to:

```text
currentSum % k = prefixSum % k
```
So instead of storing the complete prefix sum, we can store its:

```text
prefixSum % k
```

Now, apply the exact same isolation logic. What do we store in our HashMap for this problem? We store the past remainders, which is `prefixSum % k`.

Because the right side (`prefixSum % k`) is what physically sits in our HashMap, the left side (`currentSum % k`) becomes our **target to find**. You aren't subtracting anything from your current remainder (like you did with `K` earlier) because the math proves the past remainder and the current remainder must be **exactly equal**.

So instead of storing the complete prefix sum, we store its remainder, and our HashMap structure becomes:

```text
remainder → first index where it appeared
```

---

### Step 3: Why Store the First Occurrence?

Suppose the same remainder appears at:

```text
remainder = 5

index 2
index 5
index 9
```

If we are currently at index `9`, then:

```text
9 - 2 = 7
9 - 5 = 4
```

Both represent valid subarrays, but the first occurrence gives the **longer** one.

Although the problem only asks whether such a subarray exists, keeping the first occurrence is the standard and useful form of this prefix-remainder pattern.

So:

> **Store only the first index at which each remainder appears.**

Never overwrite it.

---

### Step 4: Why Do We Initially Store `0 → -1`?

This is very important.

Suppose the prefix sum itself is a multiple of `k`.

For example:

```text
nums = [2, 4]
k = 6
```

After processing both elements:

```text
prefixSum = 6
```

Therefore:

```text
6 % 6 = 0
```

We need to recognize that the subarray starting from index `0` is valid.

So before traversing the array, we pretend that:

```text
remainder = 0
index = -1
```

Therefore:

```java
map.put(0, -1);
```

Now when we reach index `1`:

```text
current remainder = 0
```

we find:

```text
0 → -1
```

and calculate:

```text
1 - (-1) = 2
```

So we correctly identify `[2, 4]` as a valid subarray of length `2`.

---

### Step 5: Why Do We Need the Length Check?

There is one additional condition in this problem:

> The subarray must contain **at least two elements**.

If the same remainder appears at the immediately previous index, then the resulting subarray has length `1`.

For example:

```text
current index = 2
previous index = 1
```

Length:

```text
2 - 1 = 1
```

This is not allowed.

So after finding an existing remainder, we check:

```text
currentIndex - previousIndex >= 2
```

If it is at least `2`, we have found a good subarray.

---

### Step 6: Complete Algorithm

Now the whole solution becomes simple:

1. Create a HashMap:

   ```text
   remainder → first index
   ```

2. Initially store:

   ```text
   0 → -1
   ```

3. Traverse the array and maintain:

   ```text
   prefixSum
   ```

4. Calculate:

   ```text
   remainder = prefixSum % k
   ```

5. If this remainder has appeared before:

   * Calculate the subarray length.
   * If length `>= 2`, return `true`.

6. Otherwise, store the remainder with its current index.

7. If we finish the array without finding such a subarray, return `false`.

### 🔑 Final Intuition

```text
We need a subarray whose sum is a multiple of k
                    ↓
Use prefix sums
                    ↓
Subarray sum = currentPrefix - previousPrefix
                    ↓
We need this difference to be divisible by k
                    ↓
(currentPrefix - previousPrefix) % k = 0
                    ↓
Both prefix sums must have the same remainder
                    ↓
Store: remainder → first index
                    ↓
Same remainder again
                    ↓
The subarray between them has sum divisible by k
                    ↓
Check that its length is at least 2
```

So the core idea to remember is:

> **Same prefix-sum remainder ⇒ the difference between those prefix sums is divisible by `k`.**

### Complexity

* **Time:** `O(N)` average
* **Space:** `O(N)`

</details>

<details>
<summary>💻 Optimal Code</summary>

```java
class Solution {

    public boolean checkSubarraySum(int[] nums, int k) {

        Map<Integer, Integer> map = new HashMap<>();

        // Remainder before the array starts
        map.put(0, -1);

        int sum = 0;

        for (int i = 0; i < nums.length; i++) {

            sum += nums[i];

            int rem = sum % k;

            if (map.containsKey(rem)) {

                // Subarray must have at least 2 elements
                if (i - map.get(rem) >= 2) {
                    return true;
                }

            } else {

                // Keep the first occurrence
                map.put(rem, i);
            }
        }

        return false;
    }
}
```

<details>
<summary>⚠️ Important Points to Remember</summary>

* We don't need the exact prefix sum; we only need `prefixSum % k`.
* **Same remainder** means the difference between the two prefix sums is divisible by `k`.
* Store the **first occurrence** of each remainder.
* `map.put(0, -1)` handles valid subarrays starting from index `0`.
* Always check that the subarray length is **at least 2**.

### 🧠 Pattern to Remember

> **Prefix Sum + Remainder + HashMap**

Whenever you see:

```text
"subarray sum is divisible by k"
```

think:

```text
prefixSum % k
```

and look for a **repeated remainder**.
