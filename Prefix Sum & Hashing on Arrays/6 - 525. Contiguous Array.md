# 525. Contiguous Array

<details>
<summary>📝 Problem Statement</summary>

Given a binary array `nums`, return the **maximum length of a contiguous subarray** containing an equal number of `0`s and `1`s.

### Example 1

```text
Input: nums = [0,1]
Output: 2

Explanation:
[0,1] contains one 0 and one 1.
```

### Example 2

```text
Input: nums = [0,1,0]
Output: 2

Explanation:
[0,1] or [1,0] contains one 0 and one 1.
```

### Example 3

```text
Input: nums = [0,1,1,1,1,1,0,0,0]
Output: 6

Explanation:
[1,1,1,0,0,0] contains three 1s and three 0s.
```

### Constraints

- `1 <= nums.length <= 10⁵`
- `nums[i]` is either `0` or `1`

</details>

---

<details>
<summary>🐢 Brute Force — 3 Loops</summary>

### 💡 Intuition

The most straightforward way is to generate **every possible subarray**.

A subarray is completely defined by:

- starting index `i`
- ending index `j`

Once we have a subarray, we can use another loop to count how many `0`s and `1`s it contains.

So we use:

```text
Loop 1 → choose starting index
Loop 2 → choose ending index
Loop 3 → count 0s and 1s in that subarray
```

For example:

```text
[0, 1, 0, 1]
 ↑        ↑
 i        j
```

Then check whether this subarray contains an equal number of `0`s and `1`s.

### Code

```java
class Solution {

    public int findMaxLength(int[] nums) {

        int maxLen = 0;

        // Choose starting index
        for (int i = 0; i < nums.length; i++) {

            // Choose ending index
            for (int j = i; j < nums.length; j++) {

                int zeros = 0;
                int ones = 0;

                // Count 0s and 1s in the current subarray
                for (int k = i; k <= j; k++) {

                    if (nums[k] == 0)
                        zeros++;
                    else
                        ones++;
                }

                // Check if counts are equal
                if (zeros == ones) {
                    maxLen = Math.max(maxLen, j - i + 1);
                }
            }
        }

        return maxLen;
    }
}
```

### Complexity

There are three nested loops:

- First loop → `O(N)`
- Second loop → `O(N)`
- Third loop → `O(N)`

Therefore:

- **Time:** `O(N³)`
- **Space:** `O(1)`

</details>

---

<details>
<summary>⚡ Better Approach — 2 Loops</summary>

### 💡 Why Can We Remove One Loop?

In the brute-force approach, for every subarray we were again traversing the entire subarray just to count `0`s and `1`s.

For example, suppose we are considering:

```text
[0, 1, 0, 1]
```

We don't need to count it from scratch.

Instead, we can **build the count while extending the subarray**.

---

### Step 1: Fix the starting point

Suppose:

```text
i = 0
```

Now gradually increase `j`:

```text
j = 0 → [0]
j = 1 → [0, 1]
j = 2 → [0, 1, 0]
j = 3 → [0, 1, 0, 1]
```

Every time we include a new element, simply update its count.

So instead of:

```text
choose subarray
        ↓
traverse entire subarray again
        ↓
count 0s and 1s
```

we do:

```text
extend subarray
      ↓
update count immediately
```

This removes the third loop.

---

### Step 2: Maintain the counts

For every starting index `i`, initialize:

```java
int zeros = 0;
int ones = 0;
```

Then move `j` from `i` to the end.

If:

```text
nums[j] == 0
```

increase `zeros`.

Otherwise increase `ones`.

Whenever:

```text
zeros == ones
```

we have found a valid subarray.

Its length is:

```text
j - i + 1
```

Update `maxLen`.

### Code

```java
class Solution {

    public int findMaxLength(int[] nums) {

        int maxLen = 0;

        // Fix the starting index
        for (int i = 0; i < nums.length; i++) {

            int zeros = 0;
            int ones = 0;

            // Extend the subarray
            for (int j = i; j < nums.length; j++) {

                if (nums[j] == 0)
                    zeros++;
                else
                    ones++;

                // Equal number of 0s and 1s
                if (zeros == ones) {
                    maxLen = Math.max(maxLen, j - i + 1);
                }
            }
        }

        return maxLen;
    }
}
```

### Why Is This Better?

In the brute force approach, for every `(i, j)` pair we were scanning from `i` to `j` again.

Now, when `j` moves one step forward, we only process the **new element**.

For example:

```text
[0, 1, 0, 1]
 ↑        ↑
 i        j
```

As `j` moves:

```text
[0]           → zeros = 1, ones = 0
[0, 1]        → zeros = 1, ones = 1  ✓
[0, 1, 0]     → zeros = 2, ones = 1
[0, 1, 0, 1]  → zeros = 2, ones = 2  ✓
```

We never recount the previous elements.

### Complexity

Two nested loops:

- **Time:** `O(N²)`
- **Space:** `O(1)`

</details>

<details>
<summary>🚀 Optimal Approach — Prefix Sum + HashMap</summary>

### 🧠 Let's Build the Intuition From the Beginning

The **better solution is `O(N²)`** because we try every starting index and extend the subarray from there.

To improve it to `O(N)`, we need to avoid explicitly considering every possible subarray.

So first, let's change the way we **look at the problem**.

---

### Step 1: Convert "Equal 0s and 1s" into a Sum Problem

We need:

```text
number of 0s = number of 1s
```

Let's give each element a value:

```text
0 → -1
1 → +1
```

Why?

Suppose a subarray contains:

```text
x zeros
y ones
```

Its sum after conversion will be:

```text
(-1 × x) + (+1 × y)
= y - x
```

For the number of `0`s and `1`s to be equal:

```text
x = y
```

Therefore:

```text
y - x = 0
```

So our original condition:

```text
Equal number of 0s and 1s
```

becomes:

```text
Subarray sum = 0
```

### 🔑 Important Transformation

We have essentially converted the problem into:

> **Find the longest subarray whose sum is `0`.**

In other words, this is now a **Longest Subarray with Sum K** problem where:

```text
K = 0
```

---

### Step 2: Recall the Prefix Sum Idea for "Longest Subarray with Sum K"

For a normal **Longest Subarray with Sum K** problem, suppose the current prefix sum is:

```text
currentSum
```

We want some earlier prefix sum such that:

```text
currentSum - previousSum = K
```

Rearranging:

```text
previousSum = currentSum - K
```

So while traversing the array, we need to check:

```text
Does currentSum - K already exist?
```

That's why we use a HashMap.

---

### Step 3: Here, `K = 0`

For this problem:

```text
K = 0
```

Therefore:

```text
previousSum = currentSum - K
            = currentSum - 0
            = currentSum
```

So instead of searching for:

```text
currentSum - K
```

we simply need to search for:

```text
currentSum
```

That gives us the key observation:

> **If the same prefix sum appears again, the subarray between the two occurrences has sum `0`, which means it contains an equal number of `0`s and `1`s.**

---

### Step 4: The "Tug of War" Analogy

Imagine the array is a **tug-of-war** game.

* Every `1` makes Team A pull the rope `1` meter to the right → `+1`
* Every `0` makes Team B pull the rope `1` meter to the left → `-1`

The current position of the rope is our **prefix sum**.

Suppose:

```text
At index i → rope is at +2
At index j → rope is again at +2
```

What happened between `i` and `j`?

The rope started at `+2` and eventually came back to `+2`.

Therefore, all the pulls between those positions must have **cancelled each other out**.

So:

```text
Number of +1s = Number of -1s
```

Which means:

```text
Number of 1s = Number of 0s
```

Therefore, the subarray between `i` and `j` is valid.

Mathematically:

```text
prefixSum[j] = prefixSum[i]

⇒ prefixSum[j] - prefixSum[i] = 0

⇒ subarray sum = 0

⇒ equal number of 0s and 1s
```

---

### Step 5: Why Does This Give the Longest Subarray?

Suppose the same prefix sum occurs multiple times:

```text
sum = 2

index →  3 .............. 9
          ↑                ↑
        first            later
```

The subarray between them has sum `0`.

Its length is:

```text
9 - 3 = 6
```

Now suppose the same sum appeared even earlier:

```text
index →  1 .............. 9
          ↑                ↑
        first            later
```

Then:

```text
9 - 1 = 8
```

is even longer.

Therefore, when we first encounter a prefix sum, we should **store its index and never replace it**.

Later occurrences can then use that earliest index to produce the longest possible subarray.

---

### Step 6: Why `map.put(0, -1)`?

Before processing the array, imagine that the prefix sum is:

```text
0
```

at index:

```text
-1
```

So we initialize:

```java
map.put(0, -1);
```

This handles subarrays that start from index `0`.

For example:

```text
nums = [0, 1]
```

After conversion:

```text
[-1, +1]
```

Prefix sums:

```text
Before array → 0
After 0      → -1
After 1      → 0
```

At index `1`, we again get prefix sum `0`.

Since we already stored:

```text
0 → -1
```

the length is:

```text
1 - (-1) = 2
```

So `[0, 1]` is correctly counted.

---

### Step 7: Complete Algorithm

Now the solution becomes very simple:

1. Convert the problem into **Longest Subarray with Sum `K`**, where:

   ```text
   K = 0
   ```

2. Maintain a running `prefixSum`.

3. Since:

   ```text
   previousSum = currentSum - K
   ```

   and `K = 0`:

   ```text
   previousSum = currentSum
   ```

4. Store:

   ```text
   prefixSum → first index
   ```

5. If the current `prefixSum` already exists:

   * We found a valid subarray.
   * Calculate its length:

     ```text
     currentIndex - firstIndex
     ```
   * Update `maxLen`.

6. If it does not exist:

   * Store its first occurrence.

### 🔑 Final Intuition

```text
Equal 0s and 1s
        ↓
Convert 0 → -1 and 1 → +1
        ↓
Equal 0s and 1s
        ↓
Subarray sum = 0
        ↓
This becomes Longest Subarray with Sum K
where K = 0
        ↓
For Sum K:
previousSum = currentSum - K
        ↓
Here K = 0
        ↓
previousSum = currentSum
        ↓
Find the same prefix sum again
        ↓
Subarray between them has sum 0
        ↓
Store first occurrence to get maximum length
```

This allows us to solve the problem in **one traversal**.

### Complexity

* **Time:** `O(N)` average
* **Space:** `O(N)`

</details>

<details>
<summary>💻 Optimal Code</summary>

```java
class Solution {

    public int findMaxLength(int[] nums) {

        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, -1); // Prefix before the array

        int sum = 0;
        int maxLen = 0;

        for (int i = 0; i < nums.length; i++) {

            // 0 contributes -1, 1 contributes +1
            sum += (nums[i] == 0) ? -1 : 1;

            if (map.containsKey(sum)) {

                // Same prefix sum means subarray sum is 0
                maxLen = Math.max(maxLen, i - map.get(sum));

            } else {

                // Keep the first occurrence for maximum length
                map.put(sum, i);
            }
        }

        return maxLen;
    }
}
```

```text
nums = [0, 1, 0, 1]
```

```text
0 → -1
```

| Index | Value | Running Sum | First Occurrence | Action                  |

|     3 |     1 |           0 | `0 → -1`         | Length = `3 - (-1) = 4` |

```text
maxLen = 4
```

<details>
<summary>⚠️ Important Points to Remember</summary>

- `0 → -1` and `1 → +1`.
- Equal `0`s and `1`s become **sum = 0**.
- Same prefix sum at two indices means the elements between them have sum `0`.
- Store the **first occurrence** of every prefix sum.
- `map.put(0, -1)` handles subarrays beginning at index `0`.
- The answer is the **maximum distance between two equal prefix sums**.

### 🧠 Pattern to Remember

> **Prefix Sum + HashMap + First Occurrence**

This same pattern is useful whenever a problem asks for the **longest subarray satisfying some balance/sum condition**.
